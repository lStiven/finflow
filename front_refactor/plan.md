# Finflow — Plan de mejora integral UX/UI

## Objetivo

Transformar Finflow en una aplicación de finanzas personales
intuitiva, interactiva y fácil de utilizar, reduciendo la
necesidad de leer documentación.

Mantener la identidad visual existente y preservar todas
las reglas financieras del sistema.

## Fases de implementación

| Fase | Objetivo | Prioridad |
|---|---|---|
| E0 | Auditoría de pantallas, componentes y APIs | P0 |
| E1 | Simplificación de textos y sistema de guías | P0 |
| E2 | Onboarding de conexión bancaria | P0 |
| E3 | Mejoras en Resumen, Transacciones y Cuentas | P1 |
| E4 | Mejoras en Facturas y Presupuestos | P1 |
| E5 | Reportes, Comercios y Centro de Guías | P1 |
| E6 | Notificaciones y métricas de experiencia | P2 |

## Prioridades

### P0 — Crítica
- Auditoría UX.
- Simplificación de contenido.
- Componentes reutilizables.
- Motor de guías interactivas.
- Onboarding bancario.
- Diagnóstico de conexión.
- Accesibilidad y validación transversal.

### P1 — Alta
- Resumen financiero interactivo.
- Administración de transacciones.
- Gestión de cuentas.
- Facturas.
- Presupuestos.
- Reportes.
- Comercios y categorías.
- Centro de guías.

### P2 — Evolutiva
- Guías para notificaciones.
- Métricas de adopción y fricción.

## Esfuerzo estimado

Total: 202–404 horas-persona.

Las estimaciones deberán revisarse después de
analizar la implementación real del proyecto.

## Principios obligatorios

1. Reducir el texto visible al mínimo necesario.
2. Enseñar las funcionalidades mientras se utilizan.
3. No repetir guías completadas o descartadas.
4. Mostrar información adicional únicamente cuando aporte valor.
5. Mantener el diseño visual actual de Finflow.
6. Reutilizar componentes y servicios existentes.
7. No mostrar estados de éxito que el backend no pueda verificar.
8. No modificar reglas financieras durante cambios de UX.
9. Implementar y probar una funcionalidad a la vez.
10. Permitir que el usuario consulte nuevamente cualquier guía.
